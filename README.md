# Ollama UI

一个用 [Flet](https://flet.dev/) 写的 Ollama 桌面客户端，重点解决终端里**没法发图片**的问题：可以直接选择图片，或按 `Ctrl+V` 粘贴截图，然后交给本地的视觉模型对话。

界面是深色本地工作台风格，支持流式 Markdown/代码/表格渲染、思考过程折叠、对话历史和本地持久化。

## 功能

- 模型列表自动读取 Ollama，并标记「视觉模型 / 纯文本」能力
- 自动识别「深度思考（thinking）」能力，顶部提供开关；关闭后不再要求模型输出思考过程
- 图片选择（可多选）与截图粘贴（`TextField.on_paste_files`）
- 图片缩略图预览、移除、点击查看大图
- 流式回答，支持 Markdown、代码块、表格、思考过程
- 回答完成后，每个代码块都有独立的「复制」按钮；整条回答也可复制
- 显示 token 数和生成速度
- 系统提示词、temperature、上下文长度（num_ctx）、计算模式（自动 / 纯 CPU / CPU+GPU 混合 / 纯 GPU）、Ollama 地址设置
- 计算模式会转换成 Ollama 的 `num_gpu`：纯 CPU 为 0，纯 GPU 使用全部层；混合模式默认约一半层，也可以自定义 GPU 层数
- 顶部会显示当前计算模式和层数；请求完成后通过 Ollama `/api/ps` 显示模型实际加载到显存的比例
- 自动只重复发送最近一次带图消息里的图片，避免上下文被历史截图迅速占满
- 输入框下方显示最近一次请求的上下文占用（prompt tokens），超过 80% / 95% 变色提醒
- 添加图片时默认压缩到最长边 1280 的 JPEG 以节省视觉 token，可在设置中关闭
- 每条回答底部提供「复制」「重新生成」；生成失败时按钮变为「重试」
- 用户消息支持「编辑并重发」：修改后删除该消息之后的回复，并从该处重新生成
- 流式输出会自动跟随到底部；向上翻看历史时暂停跟随，回到底部后恢复
- 聊天图片右上角提供拖拽手柄，可拖到输入框左侧的图片按钮复用，再次作为附件发送
- 对话历史侧栏支持搜索标题/正文、重命名、置顶、导出 Markdown、切换/删除、本地 JSON 持久化
- 设置项按「连接 / 对话 / 计算与图片 / 数据与关于」分组折叠
- 停止生成、错误提示、Ollama 离线/无模型引导
- 将图片与非视觉模型发送时给出明确警告并阻止发送
- 顶部默认显示当前计算模式；连接远程 Ollama 时会额外标注数据会发送到该服务器

## 环境要求

- Python 3.10+（本项目在 Python 3.14 + Flet 1.0.3 上验证）
- 已安装 [Ollama](https://ollama.com/download)，并能访问 `http://localhost:11434`
- Linux 桌面环境下文件选择框依赖 `zenity`（Ubuntu/Debian 一般已安装；没有的话执行 `sudo apt-get install zenity`）
- Flet 1.0+

## 安装与运行

本项目不使用 `.venv`。当前环境已经安装了 Flet 和 httpx，可以直接运行：

```bash
cd "Ollama UI"
python3 main.py
```

如果需要在一个新的 Python 环境中安装依赖，推荐用 mamba 管理环境、用 uv 安装 Python 包：

```bash
mamba create -n ollama-ui python=3.12 -y
mamba activate ollama-ui
uv pip install -r requirements.txt
python3 main.py
```

先启动 Ollama：

```bash
ollama serve
```

在另一个终端下载一个支持图片的模型（三选一，按机器配置和网络情况选择）：

```bash
ollama pull llama3.2-vision
# 或
ollama pull qwen2.5vl:7b
# 或（更小，但中文能力较弱）
ollama pull llava
```

下载完成后在应用右上角的刷新按钮更新模型列表。

> 如果只是文字对话，`llama3.2`、`qwen2.5`、`deepseek-r1` 等普通模型也可以直接用；应用会自动判断是否支持图片。

## 使用

1. 在顶部下拉框选择模型。带「视觉模型」标记的模型才支持图片。
2. 如果模型支持深度思考，顶部会出现「深度思考」开关。开启后模型会先输出思考过程，可以在助手消息的「思考过程」里展开查看；关闭后不再显示推理内容，通常响应更快。
3. 在「设置」→「计算与图片」里选择计算模式：自动、纯 CPU、CPU+GPU 混合或纯 GPU。混合模式下填 `0` 表示自动一半层，也可以输入具体 GPU 层数（会按模型层数自动收敛）。纯 GPU 模式需要模型全部放进显存；显存不够时改回自动或纯 CPU。
4. 点击输入框左侧的图片按钮，或直接把截图 `Ctrl+V` 粘贴到输入框。图片默认会先压缩；需要原图时在「设置」里关闭「压缩图片」。
5. 输入问题，按 `Enter` 发送，`Shift+Enter` 换行。
6. 生成过程中按钮会变成停止按钮；点击可中止。
7. 回答完成后，每个代码块右上角有独立「复制」按钮；整条回答也可复制。点击「重新生成」可以让模型再答一次，最后一条回答才显示该按钮。
8. 需要修改已经发送的问题时，点击用户消息下方的「编辑并重发」；保存后会删除该消息之后的回复，并从该处重新生成。
9. 按住聊天图片右上角的拖拽手柄，把它拖到输入框左侧的图片按钮，可以把这张图重新作为附件复用；也可以继续用选择文件或粘贴截图。
10. 生成时聊天区会自动跟随到底部。向上滚动查看历史会暂停跟随，回到底部后自动恢复。
11. 左侧搜索框可以按标题/正文筛选对话；对话右侧的「⋯」菜单支持重命名、置顶/取消置顶、导出 Markdown 和删除。
12. 左侧「新建对话」开启新会话；历史会话会自动保存在本地。

## 数据与隐私

- 会话、图片和设置都保存在本机：
  - `~/.ollama-ui/conversations.json`
  - `~/.ollama-ui/settings.json`
  - `~/.ollama-ui/media/`（聊天图片）
- 可以用环境变量指定其他目录：

```bash
OLLAMA_UI_HOME=/path/to/data python3 main.py
```

- 默认连接本机 Ollama（`http://localhost:11434`），对话内容不会离开这台设备。
- 如果在设置里改用远程 Ollama 地址，消息和图片会发送到该服务器；顶部会显示「远程 Ollama · 数据会发送到该服务器」的提示。
- 删除对话时，对话里的图片也会一并删除。

## 常见问题

### 发图片后为什么要等一会儿才开始输出？

这不是界面卡死。Ollama 需要先加载模型，并把图片预处理成视觉 token，完成后才会返回第一个流式 token；图片越大、模型越大，首次等待越久。应用在等待期间会显示旋转指示和「正在处理图片并生成…」，收到第一个 token 后变成「正在生成…」。

添加图片时默认会把最长边压到 1280 并转为 JPEG，这既能减少视觉 token，也能缩短首次预处理时间；需要原图时可在「设置」里关闭压缩。

### 图片在消息里显示不出来？

已修复：聊天图片现在通过 Flet 的 `RawImage` 数据通道显示，能可靠处理几 MB 的大截图；点击缩略图可以查看完整图片。修改后需要重启应用才能生效。

### 出现 `request (...) exceeds the available context size (...)` 怎么办？

这是 Ollama 的上下文窗口不够用了。Ollama 默认有时只给模型分配 4096 tokens，而历史消息、图片和思考内容很容易超过这个限制。

应用默认把 `num_ctx` 提升到 8192，你可以在「设置」里调到 16384 / 32768 / 65536 / 131072 / 262144，也可以在下方的「自定义上下文」里填写 2048–262144 之间的任意值；填写后优先于预设。上下文越大，保留的历史越多，但 KV Cache 内存会近似线性增长；131072 以上建议配合混合或纯 CPU 模式，显存不足时可能加载失败。如果某次请求仍然超限，可以新建对话后重试。

输入框下方会显示最近一次请求实际使用的 prompt tokens（例如 `上下文 1,234 / 8,192 · 15%`）；占用超过 80% 会变黄，超过 95% 变红，提示你该新建对话或调大上下文了。

另外，应用只会重复发送**最近一次带图消息**里的图片；更早的图片仍保留在本地聊天记录里，但不会再塞进模型上下文。要追问更早的图片内容，请重新附加一次图片。

## 已知限制

- 图片只支持 PNG / JPG / JPEG / WEBP / GIF / BMP，单张最大 20 MB，最多一次 8 张。
- 当前支持把**聊天记录里的图片**拖到输入框左侧的图片按钮复用；Flet 1.0 没有暴露“从系统文件管理器拖入窗口”的文件投递事件，因此仍需用文件选择或 `Ctrl+V` 粘贴截图。
- 编辑用户消息会删除该消息之后的回复；不会保留被删除内容的撤销历史。
- 导出 Markdown 时图片以文件名引用，不会把图片二进制嵌入文档。
- 历史记录只保留文本上下文和最近一次带图消息的图片；更早的图片需要重新附加才能让模型参考。
- 「纯 GPU」模式会尝试把全部层放到显卡；如果显存不够，Ollama 会加载失败，应用会提示切回「自动」或「纯 CPU」。
- 目标显存/层数由 Ollama 和显卡驱动最终决定；顶部的“实际显存”来自 `/api/ps`，是运行后的观测值，不保证与请求的 `num_gpu` 完全一致。
- 目前是单窗口桌面应用；Web 预览模式下受 Flet 会话重连影响，部分交互可能不稳定，桌面模式是主要使用场景。
